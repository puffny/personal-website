# Project Detail Pages Content Spec

Date: 2026-06-24

This document records the agreed content direction for the three main project detail pages of the personal portfolio site.

## Overall Direction

The three project pages should not use one identical long-case template. Each page proves a different capability:

- Tianmu Shuzhi: complex B-end experience delivery, design standards, and handoff quality.
- Zheli Baozhang: a lead UX case for mobile reimbursement flow improvement.
- Senben App: visual proposal, scene-based interaction, and an embedded Figma prototype.

The shared goal is credibility. Each page should show the real contribution boundary, the design decision, the evidence, and the result.

## Page 1: Tianmu Shuzhi

Recommended title:

> Tianmu Shuzhi: interaction experience and design standard optimization for a complex B-end platform

Chinese title option:

> 天目数智：复杂 B 端平台的交互体验与设计规范优化

### Positioning

This page should not be framed as a business-process strategy case. The business flows were mainly defined by the product team. The page should focus on interface experience, interaction details, visual standards, design handoff, and implementation QA.

### Role Boundary

Use this role statement:

> 业务流程由产品团队主导；我负责界面体验、交互细节、视觉规范、设计交付与还原走查。

Avoid statements like:

> 我从业务目标出发重构平台流程。

### Page Structure

1. Project background and role boundary
2. Key challenge: large information volume, many page states, long operation paths, and consistency risk
3. Information hierarchy optimization
4. Table, filter, and list experience
5. Form and operation feedback
6. Visual standards and component consolidation
7. Design handoff and implementation QA
8. Result statement

### Evidence And Metrics

Main evidence:

- Information hierarchy improvements in details pages, workbench, data cards, and module titles
- Table, filter, list, status label, batch action, empty state, and exception prompt optimization
- Form feedback, button priority, error prompt, confirmation modal, save and submit states
- Visual standards for colors, type, spacing, buttons, tables, dialogs, status labels, and page templates
- Design QA across 15 modules
- 649 interface, interaction, and implementation issues pushed toward correction

Metric wording:

> 后续咨询类工单约下降 10%。该结果受到产品流程、功能上线和团队协同等多因素影响，我的贡献主要集中在界面信息层级、操作反馈与设计一致性优化。

Large numbers such as 1500+ / 260 should not become primary proof unless their scope can be explained clearly. They can appear as background scale if needed.

## Page 2: Zheli Baozhang

Recommended title:

> Zheli Baozhang: mobile reimbursement flow experience upgrade

Chinese title option:

> 浙里报账：移动端报销流程体验升级

### Positioning

This is the strongest standard UX case among the three pages. It can be presented as a lead case because the core project was done independently.

### Role Statement

Use this role statement:

> 我主导完成浙里报账移动端核心体验改版，围绕首页信息架构、智能报销流程、单据筛选、电子发票详情和行程管理等模块，重构用户完成报销任务的关键路径。

### Page Structure

1. Project background: mobile reimbursement involves trips, invoices, forms, and approval status
2. My role: independently led the core mobile experience upgrade
3. Core problems: too many steps, scattered information, unclear approval status, high search and judgment cost
4. Design goal: shorten the path, reduce form-filling pressure, clarify status and relationships
5. Key optimizations:
   - Home information architecture
   - Smart reimbursement flow
   - Form filtering and lists
   - Electronic invoice details
   - Trip management
6. Results:
   - Reimbursement time shortened by 40%
   - Consultation tickets decreased by 18%
   - User satisfaction increased by 46%
7. Project value: proves capability in leading complex mobile task-flow design

### Tone

This page can use stronger cause-and-effect than Tianmu, but still avoid claiming every metric came from one isolated page change. Frame the data as version-level comprehensive results after the experience upgrade.

## Page 3: Senben App

Recommended title:

> Senben App: scene-based interaction design for the planning module

Chinese title option:

> 森本 App：计划书模块的场景化交互设计

### Positioning

This is a short case, not a long UX case. It should prove visual expression, scene-based interaction, proposal communication, and prototype presentation.

### Page Structure

1. Project background: a news app where the client cared about the planning / package recommendation module
2. Before / After:
   - Put the old UI and new UI on the second screen
   - Explain that the old version worked like ordinary content cards
   - Explain that the new version turns the content into a desk-based planning-book browsing scene
3. Scene-based design decision:
   - Desk
   - Planning book
   - Page turning
   - Click-based content switching
4. Final design + Figma interactive prototype:
   - Merge the three final app page images and the embedded Figma prototype into one section
   - Desktop layout: final pages on one side, phone-ratio Figma iframe on the other
   - Mobile layout: final pages first, Figma prototype below
   - Include a fallback button to open the Figma prototype externally
5. Result:
   - The proposal was accepted by the client
   - It became the core interactive showcase in the project detail page

### Core Wording

Use this idea:

> 旧方案能够展示信息，但缺少计划书被浏览和选择的场景感。我将抽象的套餐内容转化为桌面上的计划书翻阅体验，让用户更容易感知不同方案之间的差异，也让甲方能直接看到最终交互效果。

## Cross-Page Rhythm

Tianmu should feel professional and restrained: clear boundaries, design standards, and handoff credibility.

Zheli Baozhang should feel like a complete UX case: problem, flow, design action, and data result.

Senben should feel short and direct: before/after, visual decision, and interactive prototype.

The three pages should read as three different types of proof:

- System delivery
- Flow leadership
- Visual interaction
