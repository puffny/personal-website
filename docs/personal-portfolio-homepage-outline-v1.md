# 05 Design Thinking

## 屏幕目标

表达设计判断和方法观。  
这一屏回答：我怎么看设计，为什么适合资深 UIUX。

## 视觉结构

建议不要做成文章，采用“观点 + 三个关键词”的形式。

```text
左侧：
Design Thinking
主文案

右侧：
Clarity / Efficiency / Consistency 三个关键词
```

## 文案定稿

```text
Design Thinking

好的设计不只是界面表现，
而是对业务目标、用户行为、信息结构和落地成本的综合判断。

我习惯先理解问题背后的真实场景，
再通过信息层级、交互路径和视觉系统，
把复杂产品转化为清晰、稳定、可执行的体验方案。
```

## 三条原则

### 01 Clarity

```text
让复杂信息变清晰。

通过信息分层、视觉优先级和结构化表达，降低用户理解成本。
```

### 02 Efficiency

```text
让关键路径更高效。

围绕高频任务和核心目标优化操作流程，减少不必要的判断和重复操作。
```

### 03 Consistency

```text
让体验能够持续复用。

通过设计规范、组件沉淀和跨端一致性，提升产品体验与团队协作效率。
```

## 注意事项

- 这一屏不放项目图。
- 保持克制，像设计观，不像长篇文章。
- 可用大字号英文关键词作为视觉主体。

# 06 AI Lab

## 屏幕目标

展示 AI 协作实验和学习能力。  
这一屏把“用 AI 做个人网站”变成加分项，但不要写成“我会很多 AI 工具”。

## 视觉结构

```text
左侧：
AI Lab 标题 + 文案

右侧：
流程节点 / 命令行片段 / 代码窗口 / 动效轨迹
```

视觉重点：

```text
设计判断 + AI 协作 + 结果迭代
```

不要变成：

```text
我会写代码
我会部署
我会用很多工具
```

## 文案定稿

```text
AI Lab

An experiment in AI-assisted design workflow.

这个网站也是我的一次 AI 协作实验。

我将自己的作品集内容、职业经历和设计判断整理为结构化资料，再通过 AI 辅助完成内容重构、代码生成、动效实验和页面迭代。

对我来说，AI 不是替代设计判断的工具，而是帮助设计师更快验证想法、扩展表达和提升执行效率的协作者。

真正重要的不是生成更多方案，而是判断什么值得保留、什么应该删除，以及如何让最终结果保持清晰、准确和有个人识别度。
```

## 流程节点

建议使用通用版：

```text
Content Structure
内容重构

Visual Direction
视觉方向

Prototype & Motion
原型与动效

Code Build
代码实现

Deploy & Iterate
上线与迭代
```

## 核心句

```text
真正重要的不是生成更多方案，而是判断什么值得保留、什么应该删除。
```

## 注意事项

- 不要把这一屏做成开发者作品集。
- 不要堆工具名。
- 重点是 AI 协作背后的设计判断。

# 给 Codex 的执行要求

## 技术方向

- 可使用 React + Vite 重构。
- 保持极简、现代、克制的视觉风格。
- 首页需要支持视频背景。
- Selected Works 需要支持点击或 hover 切换右侧展示图 / 视频。
- 保留后续扩展项目详情页的结构入口。
- Portfolio PDF 按钮需要预留下载链接。
- Copy Email 按钮需要支持复制邮箱。

## 内容规则

- 不要主动修改已定文案。
- 不要额外添加未确认模块。
- 不要把 More Works 加回首页。
- 不要把项目详情内容塞进首页。
- 不要在 Hero 放联系方式。
- 不要把 AI Lab 写成技术炫技模块。

## 视觉规则

- 第一屏以个人视频为核心记忆点。
- 第二屏偏职业可信度。
- 第三屏偏能力结构化。
- 第四屏偏项目展示和视觉吸引。
- 第五屏偏设计观点。
- 第六屏偏 AI 协作实验。
- 第七屏偏联系收尾。
